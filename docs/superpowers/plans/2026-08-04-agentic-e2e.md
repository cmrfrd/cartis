# Agentic E2E Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `bun run e2e:agent` — an opencode-driven LLM drives real Chrome against the real dev server to accomplish user-voice objectives; a mechanical harness (not the LLM) judges typed criteria — per `docs/superpowers/specs/2026-08-04-agentic-e2e-design.md`.

**Architecture:** One runner script owns three processes per scenario: the dev server on a scratch `CARTIS_DATA_ROOT`, a driver opencode server (spawned with the SAME `createOpencode` the app uses) whose config attaches the `chrome-devtools-mcp` browser-tool server and whose cwd is a scratch dir (never the repo — sessions are project-scoped), and sequential scenario sessions. Verification: `fs` criteria run directly in the runner; `page` criteria are fixed JS snippets relayed through the driver's evaluate tool and parsed from a fenced JSON block.

**Tech Stack:** bun (runner script), `@opencode-ai/sdk` `createOpencode` (already a devDep), `chrome-devtools-mcp` via `bunx` (no package.json entry; requires local Chrome), plain `node:fs/promises`.

## Global Constraints

- **Canary gates everything** (spec §Known risk): Task 1 must PROVE the driver session can call a chrome-devtools tool before Tasks 2–5 proceed. Fallback: write `opencode.json` into the driver cwd. If neither works: STOP, report, redesign.
- The ONLY `src/` change: `agentBridge.ts:1337` `DATA_ROOT` becomes `process.env.CARTIS_DATA_ROOT ?? 'cartis-data'` (config-reachable file — keep relative `.ts` imports, no `@/`).
- The driver's cwd is NEVER the repo. `REPLICATE_API_TOKEN` is STRIPPED from the dev-server child env (stub images).
- **Strict port (data safety):** the app under test runs at `APP_URL = http://localhost:5199` via `bun run dev -- --port 5199 --strictPort`; the runner ABORTS if 5199 is listening before spawn. NEVER touch 5173 — the user's live server (and REAL data) is usually there.
- Objectives are TEMPLATED: harness substitutes `{{APP_URL}}` and `{{STAGE_DIR}}` (absolute driver-cwd path) before prompting. Driver model: `E2E_DRIVER_MODEL ?? OPENCODE_MODEL`.
- Verdicts separate DRIVER outcome (done/blocked/timeout) from CRITERIA outcome; `--retries N` (default 0) re-runs driver-failures only; never weaken a criterion to pass. Final full-page screenshot per scenario into the run dir.
- The runner uses the RAW SDK client (unwrap `{data}` inline) — do NOT import `agentBridge.ts` into e2e (it drags the vite-tied server graph into a bun script).
- Scenarios run SEQUENTIALLY; `rm -rf` + recreate scratch dirs per scenario; fresh dev server per scenario; teardown verifies the process tree (vite, both opencodes, MCP's Chrome) actually died.
- Pass/fail comes ONLY from `Criterion` checks executed by the runner. The driver's `DONE`/`BLOCKED` text is evidence, never a verdict.
- `bun run verify` stays green per task: add `"e2e"` to `tsconfig.json` include (typecheck it); vitest globs (`src/**`) are unaffected; biome covers `e2e/`; add `e2e/runs/` and `e2e/.scratch/` to `.gitignore`.
- SDK facts (verified): `Config.mcp: { [name]: McpLocalConfig }` with `{ type: 'local', command: string[], environment?, enabled? }`; `Config.permission` exists — set permissive values so driver tool calls don't block.

```ts
import { createOpencode } from '@opencode-ai/sdk';

export async function spawnDriver(cwd: string): Promise<Driver> {
  const prevCwd = process.cwd();
  process.chdir(cwd); // opencode scopes sessions to cwd — NEVER the repo
  try {
    const model = process.env.E2E_DRIVER_MODEL ?? process.env.OPENCODE_MODEL;
    const { client, server } = await createOpencode({
      port: 0,
      config: {
        ...(model ? { model } : {}),
        mcp: {
          browser: { type: 'local', command: ['bunx', 'chrome-devtools-mcp@latest'], enabled: true },
        },
        permission: { edit: 'allow', bash: 'allow', webfetch: 'allow' },
      },
    });
    return { client, close: () => server.close() };
  } finally {
    process.chdir(prevCwd);
  }
}
// Raw SDK responses wrap payloads as { data } — unwrap inline at call sites.
```
(Adjust `permission` keys to the SDK's actual `Config['permission']` type when writing.)
(If `createOpencode` ignores cwd-at-call-time, fallback inside this task: write `${cwd}/opencode.json` with the same config object and spawn with a minimal config. Adjust `permission` keys to whatever the SDK type actually requires — inspect `types.gen.d.ts` `Config['permission']` when writing.)
