# Agentic E2E Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `bun run e2e:agent` — an opencode-driven LLM drives real Chrome against the real dev server to accomplish user-voice objectives; a mechanical harness (not the LLM) judges typed criteria — per `docs/superpowers/specs/2026-08-04-agentic-e2e-design.md`.

**Architecture:** One runner script owns three processes per scenario: the dev server on a scratch `CARTIS_DATA_ROOT`, a driver opencode server (spawned with the SAME `createOpencode` the app uses) whose config attaches the `chrome-devtools-mcp` browser-tool server and whose cwd is a scratch dir (never the repo — sessions are project-scoped), and sequential scenario sessions. Verification: `fs` criteria run directly in the runner; `page` criteria are fixed JS snippets relayed through the driver's evaluate tool and parsed from a fenced JSON block.

**Tech Stack:** bun (runner script), `@opencode-ai/sdk` `createOpencode` (already a devDep), `chrome-devtools-mcp` via `bunx` (no package.json entry; requires local Chrome), plain `node:fs/promises`.

```ts
import { createOpencode } from '@opencode-ai/sdk';
import { type OpencodeClient, opencodeClientOf } from '../src/server/agentBridge.ts';

export async function spawnDriver(cwd: string): Promise<Driver> {
  const prevCwd = process.cwd();
  process.chdir(cwd); // opencode scopes sessions to cwd — NEVER the repo
  try {
    const { client, server } = await createOpencode({
      port: 0,
      config: {
        ...(process.env.OPENCODE_MODEL ? { model: process.env.OPENCODE_MODEL } : {}),
        mcp: {
          browser: { type: 'local', command: ['bunx', 'chrome-devtools-mcp@latest'], enabled: true },
        },
        permission: { edit: 'allow', bash: 'allow', webfetch: 'allow' },
      },
    });
    return { client: opencodeClientOf(client), server, close: () => server.close() };
  } finally {
    process.chdir(prevCwd);
  }
}
```
(If `createOpencode` ignores cwd-at-call-time, fallback inside this task: write `${cwd}/opencode.json` with the same config object and spawn with a minimal config. Adjust `permission` keys to whatever the SDK type actually requires — inspect `types.gen.d.ts` `Config['permission']` when writing.)
